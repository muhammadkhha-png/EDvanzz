## Context (what already exists — do not redo)

Phase 1 (Auth) is complete. The Swagger example infrastructure uses a **provider registry**
(Option A), already wired and working. The relevant files:

- `Edvanz.API/Filters/IEndpointExampleProvider.cs` — defines `IEndpointExampleProvider`,
  the abstract base `EndpointExampleProvider` (with `SuccessEnvelope` / `FailureEnvelope`
  helpers), and the `EndpointExampleSet` record. `EndpointExampleSet` supports **both**
  single examples (`RequestBody`, `Responses`) **and** named dropdown examples
  (`RequestBodyExamples`, `ResponseExamples`).
- `Edvanz.API/Filters/SwaggerExamplesFilter.cs` — the thin `IOperationFilter`. Injects
  `IEnumerable<IEndpointExampleProvider>`, normalizes the route (lowercased, no
  leading/trailing slash), and delegates to the first provider that owns the route.
  **Never edit this file to add a module.**
- `Edvanz.API/Filters/AuthExampleProvider.cs` — reference implementation. Mirror its style.
- `Edvanz.API/Filters/SubscriptionExampleProvider.cs` — second reference implementation.
- `Edvanz.API/Program.cs` — providers are registered as singletons **before**
  `AddSwaggerGen`, and `c.OperationFilter<SwaggerExamplesFilter>()` is inside it.

The unified response envelope (from `ApiBaseController.ToResponse`) is:
`{ "success": bool, "message": string, "data": object|null }`.

## Auth & tenancy facts (state these in the XML docs)

- Class-level `[Authorize]` + per-action `[ModulePermission(StudentConstants.ModuleName, ...)]`.
- `teacherId` is **always** resolved from the JWT via
  `ModuleSixApiBaseController.ResolveTeacherIdAsync()` — never from the route or body.
  Assistants resolve to their owning tutor; SuperAdmin bypasses the permission filter.
- These endpoints manage **TeacherStudent** records (student data owned by a teacher),
  NOT `StudentUser` login accounts.

## Implementation steps (do in order)

1. **Read** `TeacherStudentController.cs` and list every endpoint with its verb, normalized
   route, permission, request DTO, and params.
2. **Read** each referenced DTO; record exact property names/casing.
3. **Verify** the `Result.Failure` default status code (see open issue above).
4. **Edit the controller:** for each action add/upgrade `///` XML docs (`<summary>`,
   `<remarks>` incl. auth requirement and tenancy note, `<param>` per parameter, `<response>`
   per status) and complete `[ProducesResponseType]`. Change behavior of nothing — docs and
   attributes only.
5. **Create** `Edvanz.API/Filters/TeacherStudentExampleProvider.cs`:
   - `public sealed class TeacherStudentExampleProvider : EndpointExampleProvider`.
   - `public override EndpointExampleSet? GetExamples(string method, string route)`.
   - One `if (method == "..." && route == "...")` branch per endpoint, returning an
     `EndpointExampleSet`. Routes must be the **normalized** form the filter produces
     (lowercase, no leading/trailing slash, placeholders intact, e.g.
     `api/teacherstudent/students/{studentid}`).
   - Use `SuccessEnvelope(...)` / `FailureEnvelope(...)` from the base class.
   - For create/update, build request-body examples from a real seeded teacher's student
     (e.g. a student named "Youssef Tarek" style). For list endpoints, return a
     `PaginatedResponse`-shaped `data` object (`data`/`page`/`pageSize`/`totalCount`) — match
     the exact shape used in `SubscriptionExampleProvider`'s `history` example.
   - Where an endpoint benefits from multiple accounts (e.g. teacher1 vs teacher2 scope),
     use the named `RequestBodyExamples` / `ResponseExamples` dropdown fields.
   - Fresh `JsonObject`/`JsonArray` instances per example (a `JsonNode` can have only one
     parent — reusing one throws at runtime).
   - End with `return null;`.
6. **Register** in `Program.cs`, next to the existing registrations, **before** `AddSwaggerGen`:
   ```csharp
   builder.Services.AddSingleton<IEndpointExampleProvider, TeacherStudentExampleProvider>();
   ```
7. **Build** the solution. Fix compile issues.
